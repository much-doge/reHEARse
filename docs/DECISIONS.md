# Decisions

## D-001 — Learning before assessment

Status: accepted

The first mode is a repeatable learning loop, not TOEFL simulation. Practice
conditions arrive later as a distinct capability.

## D-002 — No-score learning invariant

Status: accepted

Learning submissions and feedback contain no numerical performance fields.
Game points, if added, live in a separate capability and never feed learner
diagnostics or profiles.

## D-003 — Evidence, not mind reading

Status: accepted

The system describes what a learner's notes/reconstruction evidence,
contradict, or leave unknown. “Insufficient evidence” is a valid output.

## D-004 — Bilingual feedback is atomic

Status: accepted

English and Indonesian text are required together in the feedback contract and
stored in one version. A partial translation is an invalid provider result.

## D-005 — Modular monolith first

Status: accepted

Use one Next.js Node application, PostgreSQL, and private volume under Compose.
Maintain ports and adapters inside the repository. Split processes only after a
measured scaling, reliability, or security requirement.

## D-006 — Local identity first

Status: accepted

Deliver email/password accounts for the MVP. Google SSO is a future identity
adapter and must not alter learner ownership or attempt records.

## D-007 — PostgreSQL owns durable state

Status: accepted

Use append-only SQL migrations and transactions. Do not introduce a queue or
cache service in the first slice.

## D-008 — Provider-neutral structured feedback

Status: accepted

Use a narrow feedback-provider port and validate `listening-feedback.v1`.
Provide an explicitly labeled deterministic demo adapter and an optional OpenAI
Responses adapter. Provider output never writes directly to persistence.

## D-009 — Self-paced playback first

Status: accepted

Only self-paced playback is available in the MVP. Teacher-led synchronized
playback needs its own realtime contract, late-join behavior, clock-drift
policy, and classroom failure design before implementation.

## D-010 — Node and container baseline

Status: accepted

Use Node 24 LTS in production containers, Next.js 16 App Router, React 19,
TypeScript, PostgreSQL 18, pnpm, and multi-stage Docker builds. The host may use
another supported Node LTS for local checks.

## D-011 — Product name

Status: accepted

The product is named **reHEARse**. The emphasis on “HEAR” connects deliberate
practice with repeated listening without framing the experience as a test. Use
the stylized name in learner-facing copy and `rehearse` for machine identifiers
such as package and Compose project names. Existing `LFL-*` work IDs remain
unchanged so their Git and ledger lineage stays stable.

## D-012 — Private object storage delivers media directly

Status: accepted

Use a provider-neutral media-store port with local disk for development and an
S3-compatible adapter for Backblaze B2. Buckets remain private. After server
authorization, remote playback receives a short-lived signed download URL so
audio bytes travel from object storage to the learner rather than through the
application host. Object keys are generated by the server and stored with
checksum, media type, byte size, and provider provenance. Credentials and raw
bucket URLs never enter browser DTOs or logs.

## D-013 — Activity packages are versioned import maps

Status: accepted

Teacher and operator imports use `listening-activity-package.v1`. The contract
has a small required spine—identity, bilingual prompt, transcript, teacher
guide, media metadata, and source provenance—plus typed questions, optional
timed transcript segments, and JSON extension maps. Importing an existing slug
creates a new immutable activity version; it never edits an earlier version or
attempt. Publication remains an explicit import-time choice.

## D-014 — Isolated production and optional public media

Status: accepted for LFL-006. Supersedes D-012 only for explicitly public media.

Public, authorized audio may use the existing najala-dumpster bucket under
rehearse/media only. Private signed delivery remains available. Public URLs
are stable and audio bypasses the application host. Never publish private
transcripts, learner evidence, credentials, logs or backups to that bucket.
Imports generate activity-ID/version/random object keys, refuse existing-key
uploads, and store bucket, hash, size and source lineage. Publication commits
only after upload succeeds.

Production has a separate rehearse Compose project, PostgreSQL volume/network,
explicit secrets and a protected one-time administrator bootstrap. Demo seeding
is excluded. The operator explicitly authorized binding 192.168.8.63:3001
for an external Cloudflare instance; this supersedes the requested loopback
binding for this deployment only. Cloudflare routing stays operator-owned.
The operator authorized copying only the existing LLM key from Writing Analysis
Studio; no other credentials or workload changes are authorized.

B2 live canary returned HTTP 501 for conditional PutObject (If-None-Match).
The adapter therefore HEAD-checks only the exact newly generated key and refuses
an existing object. Imports always generate fresh random keys per content version.
This provider has no atomic compare-and-create guarantee: a concurrent writer
using the same random key between HEAD and PUT could race. Dedicated key scope,
operator-only imports and 128-bit random identifiers avoid reusing published keys.
No bucket listing or existing object modification is needed.

## D-015 — Teacher-led recreational classroom (LFL-007)

Accepted. Extends D-009 with teacher speaker/projector playback, not synchronized
student audio. PostgreSQL owns phase/revision and quiz deadlines. Polling recovers
after disconnect; late joins enter the current phase without retroactive points.
Teacher transitions serialize under a room lock and require the observed revision.
A failed request is reconciled by reading state, not blindly repeating a transition.

The loop is listen, untimed externalization, timed recreational quiz, review with
one listening cue, replay and discuss, then next. Game points (1000 plus at most
200 for speed) never enter individual attempts, feedback, profiles or exports.
Teacher controls review and may finish early. Guest aliases are generated; no
student account or name is required. Cloud submissions are immutable, moderated
before public display, rendered as text, and never sent to an AI provider.
Room membership uses a random HttpOnly token stored only as a hash. Rooms expire
after 24 hours. Answer keys and cues remain absent from student DTOs before review.
Source clips are operator-provided; optional audio transcription is source
preparation only, sends audio without learner data, and is teacher-advisory.

## D-016 — Confidential sources and teaching language (LFL-008)

Accepted at the operator's request. Source supplier names, archive/package
identifiers, original item ranges and provenance labels are confidential.
Preserve immutable source evidence privately; never copy source metadata into
public presentation fields, page metadata, browser payloads or feedback copy.
The presentation boundary supplies neutral activity labels and classroom titles
for both current and previously created rooms, without modifying their evidence.

Write instructions around the learner's next action: listen, summarize, compare,
replay and revise. Remove slogans, repeated assessment disclaimers and internal
provider/validation terminology. Retain paired English/Indonesian guidance and
brief, practical explanations of game points. The underlying separation of
learning feedback and game points is unchanged.

The operator chose to keep the Git repository public and scope this cleanup to
the live application; repository history and visibility are unchanged. In
learner-facing copy, prefer response, explanation, and details in the audio over
"evidence". Preserve stored feedback and apply legacy wording changes only at
the presentation boundary. Future feedback prompts use the same language.

## D-017 — Role-aware practice preview (LFL-009)

Teacher and administrator activity views are previews. Only learner accounts
may submit individual listening responses. The page must communicate this
before data entry and omit save controls for previews; the server guard remains
authoritative. Save errors explain authentication, role, validation and origin
failures in English and Indonesian without clearing text or logging it. An
unconfirmed save must direct the learner to check history before retrying; a
network failure does not prove that a response was not stored.

## D-018 — Reflection while feedback waits (LFL-010)

Pending submissions show a small optional, bilingual listening reflection:
choose situation, speaker purpose or a detail to check, then express whether
another listen would help. Choices stay in browser memory and do not enter
learning history or provider requests. Animation honors reduced motion; status
never claims a save has completed or invents provider progress. Loading takes
precedence over prior feedback.

Feedback addresses the learner directly with you/kamu, in short, warm teaching
sentences. Avoid third-person reports and irrelevant absence-of-history remarks.
The next listening target is one audio cue, not an essay task or revealed answer.
Stored feedback remains immutable; narrowly matched legacy phrasing is adjusted
only for display, while future requests use the versioned prompt.

At the operator's further instruction, missing audio meaning must be elicited,
not supplied: acknowledge only details present in the learner's current text;
ask one open question about a speaker, moment or relationship for gaps and
contradictions. This restriction applies to summaries and observations as well
as replay targets. Do not introduce missing source names, solutions or answers.

## D-019 — Confirm saves without resubmitting (LFL-011)

A save acknowledgement and feedback availability are distinct. New clients
retain one random submission key for an unchanged response; server-side
learner/key uniqueness, a payload digest and an advisory transaction lock
return the same immutable attempt on retry. A changed payload under the same
key is rejected. Keys are optional for older clients. API responses use
`attempt-result.v2`; owned lookup by submission key or attempt ID is private
and uncached, with learner role enforced. No submitted text enters URLs/logs.

After a lost POST response, the client looks up that key before reporting
uncertainty. Saved-but-unavailable feedback is shown honestly and can be checked
without another submission. GET absence alone does not prove an in-flight save
will not complete; a user retry reuses the key. A new revision gets a new key.
The provider timeout covers response-body consumption as well as headers.
Existing attempts and feedback stay unchanged; migration 009 is additive.

## D-020 — Bound feedback latency and speaker reference (LFL-013)

Accepted. Second person in generated feedback refers only to the learner. A
person inside the recording must use an explicit role or third-person pronoun;
transcript dialogue must never turn the speaker's circumstances into the
learner's circumstances.

Production feedback uses minimal reasoning, a 1,200-token generation ceiling
and a 30-second complete-response deadline. Successful records retain only
content-free byte counts, provider token usage and header/total latency. This
observability does not authorize logging prompts or learning content.

Attempt persistence remains before the provider call. Feedback is still
synchronous in LFL-013; moving it to a durable worker is a separate accepted
optimization gate after deployed measurements demonstrate the need. An
untracked in-process background promise is not an acceptable substitute.

## D-021 — Acknowledge the attempt before generating feedback (LFL-014)

Accepted. `POST /api/attempts` commits and returns the immutable attempt with a
pending feedback status without contacting OpenAI. The learner client then
requests generation through a separate same-origin, learner-owned endpoint.
PostgreSQL serializes generation by attempt; the unique feedback row makes
repeated requests idempotent. A lost generation request leaves a durable
pending attempt that can be requested again.

This is deliberately two-phase and client-triggered, not an untracked server
promise. It improves save latency without adding a broker or permanent worker.
It does not claim to reduce the provider's own inference time. A background
worker remains conditional on evidence that feedback must finish while the
learner is disconnected.

Generated feedback is a direct conversation with the student. Prompt v5 bans
reviewer narration such as `the learner notes`; conservative presentation-only
normalization protects the current UI without rewriting immutable stored
feedback.

## D022 — bounded individual listening game (LFL-016)

The operator requested the playable game following LFL-015. Bootstrap one
source-backed conversation with four media-time spans, a recreational board,
owned saved runs and append-only actions. Game position remains isolated from
instructional feedback/history and is not a listening metric. Signed teachers
and admins may try a solo game; classroom joins require the learner role.

First choices and follow-up choices use authored server-only keys. A repair
records a brief learner explanation and checks one meaning relationship through
a separate follow-up choice. This does not certify the whole explanation: AI
provides an optional listening nudge, never the progress gate. After one attempt,
explicit supported review can close the task; repeated difficulty adds no debt.
Teacher assistance closes a task with a saved reason. The first playable release
has one finite floor; later floors, video and general import tooling remain open.

Support is guaranteed rather than randomized. Replay and hints provide the
initial perks; random cosmetics/catch-up variations await a classroom trial.
The public teacher projection excludes help usage and mistake counts; teacher
controls remain private. Session PINs select an owned classroom session and do
not replace sign-in. Media checksum protects timing/content alignment.

## D023 — Session-aware navigation and reauthentication (LFL-017)

The brand opens the public homepage. Its account links reflect the actual
database-backed session. Signed-in users bypass login/register pages. Protected
page redirects preserve only allowed app paths and validated PINs; arbitrary
external destinations and authentication loops are rejected. Expired sessions
on mounted activities show bilingual reauthentication guidance with a new-tab
link, preserving unsaved text. A network failure never implies expiry. Session
checks reveal only an authenticated boolean, with private no-store caching.
Existing thirty-day expiry and role/ownership guards remain unchanged.

## D024 — Teacher stage and restrained ambience (LFL-018)

Use a teacher-only landscape projection of the existing route, with larger
board occupancy, compact private controls and fullscreen support. Individual
board geometry and progression remain unchanged. Kenney CC0 particles receive
subtle original animation; reduced motion disables it. Optional credited CC BY
music is default off and available only before active learners or after their
finish/session closure, with manual volume and tab-hide pause. It never plays
on learner pages. Reward/tension changes remain proposals in
GAMEPLAY_ENERGY_PLAN.md, not silently introduced progression rules.

## D025 — Whole-section games with durable passage checkpoints (LFL-021)

Accepted at the operator's request. New games combine the two conversations and,
separately, the three talks. Each has one run/session and a final finish. Passage
completion opens an explicit checkpoint, then a committed continue action changes
the recording and board. Replay/support remains bounded within the current passage;
no new debt or points are introduced. All recording versions are pinned at start.
Historical single-recording content and saved routes remain readable.

The teacher can select a passage board and see participant locations across
passages. Projection never shows help usage, repair counts or learner explanations.
Board position stays a game mechanic, not a listening measurement.

## D026 — Teacher release and pre-game identity (LFL-022)

New class sessions begin in a visible waiting room. Each learner confirms a
bounded pseudonym and character before readiness; the owning teacher explicitly
starts the class game. Both gates are checked server-side and hide playback/
questions until released. Late joins remain possible. Existing sessions/runs
migrate as started/ready; character/name choices are pinned per run and locked
at readiness. Completed runs return to an owned activities-dashboard recap,
without instructional scores or ranks. Passage checkpoints remain individual.

## D027 — Separate ProTEFL course companion and Test Center (LFL-027)

Accepted for planning. The ProTEFL/TOEFL ITP course companion lives under
`apps/protefl-center/` in this Git repository. A shared repository is a source
management choice, not permission to share runtime state. The Test Center has
its own product charter, application boundary, deployment configuration,
database schema or database, access-control policy and verification receipts.
The existing reHEARse application remains at the repository root and must stay
runnable while the companion is developed.

The Test Center may eventually administer a formal full-length diagnostic or
placement test and report section and total results. This is a narrow exception
to the reHEARse no-score learning invariant: assessment results must never be
written into reHEARse attempts, listening feedback, games, learner history or
teacher diagnostics. Course activities outside an explicitly labeled test
remain learning activities and must not quietly become scored assessment.

ConTEFL archive files, answer keys, transcripts, credentials, candidate data
and actual test responses are owner-only material. They stay outside Git in an
ignored private path. The public repository may contain only neutral schemas,
synthetic fixtures and provenance records that do not expose protected source
content. Before any real test is digitized or administered, the owner must
record source authorization, test form/version, scoring interpretation,
retention policy, access roles, incident/recovery procedure and an explicit
publication gate.

The first slice is planning and a synthetic walking skeleton. Do not add shared
identity, shared tables, Zoom automation, asynchronous jobs, payment, marketing
CMS or deployment infrastructure until a concrete journey requires it. Links
between the companion and reHEARse may be added later through narrow public
routes; direct cross-product database reads are not authorized.

## D028 — Closed supervised Test Center pilot through reHEARse identity (LFL-028)

Accepted for the first course pilot. An authenticated reHEARse learner may open
one explicitly assigned ProTEFL listening test through a protected route. The
route adapter may pass the already authenticated actor identifier into the Test
Center application boundary; Test Center domain and persistence code must not
query reHEARse identity, attempts, feedback, games or learner-history tables.

For this transitional same-origin pilot, Test Center records use separately
named `protefl_*` tables in the existing PostgreSQL service. This is operational
co-location, not shared product state. Test forms, keys, responses, submissions,
raw results and remedial attempts remain owned by the Test Center and have no
foreign keys or write paths into reHEARse learning records. A future separate
runtime or database must be able to replace the route and persistence adapters
without changing the assessment domain.

The pilot is closed and supervised. It may report raw correct/incorrect item
outcomes only after immutable submission and may create a separate remedial run
containing missed items. It must not claim an official TOEFL score, validated
placement interpretation, source-complete status or classroom verification.
The source owner authorized closed course-internal digitization in the LFL-028
request; protected source details, transcripts and keys remain in the ignored
Test Center private workspace.

## D029 — English-only rendered product language (LFL-029)

Accepted at the operator's request. All learner, teacher, administrator and
Test Center interfaces render English only. This supersedes the earlier
bilingual presentation requirement in D023 and the original product and design
specifications; it does not weaken the listening-learning, no-score, privacy or
assessment-isolation invariants.

Existing immutable records and versioned contracts may retain paired `en` and
`id` fields for backward compatibility and auditability. The application must
not delete or rewrite historical attempts, feedback, preparation content or
test records merely to change presentation language. UI adapters select the
English field, and new public-facing copy is authored in English. Removing the
legacy Indonesian storage shape requires a separate additive migration and
contract-version decision; it is not part of this display-only change.

## D031 — Assigned Test Center resources and composed diagnostic (LFL-032)

Accepted for the next ProTEFL Test Center slice. Signing in does not grant a
learner access to every published resource. A teacher or administrator
controls which versioned resources are visible and assigned. The learner home
lists only resources the current learner is authorized to access; start,
resume, media, result and review routes enforce the same assignment and
ownership rules server-side. Draft, hidden, expired and unassigned resources
must not be discoverable by guessing an identifier. Hiding a resource prevents
new starts; an already-started attempt remains resumable unless an authorized
teacher explicitly invalidates it with an audit record.

The first runtime slice uses single-use, resource-scoped invite codes because
the Test Center must not query the reHEARse user directory. It stores only a
hash of each invite and the authenticated opaque actor identifier on claim.
Existing supervised Listening attempts are backfilled as assignments to
preserve pilot access; new starts require an active assignment and a published
resource. This slice does not yet create or publish a composed diagnostic.

The full diagnostic is a new immutable, versioned package in the ProTEFL Test
Center. It may pin the existing supervised Listening form as one section and
add separately reviewed Structure and Reading sections. Reuse the pilot's
server-authoritative timing, idempotent mutations, recovery, ownership checks,
media delivery and immutable submission patterns, while keeping Listening's
section-specific playback rules encapsulated. Diagnostic assignments,
responses and results stay in the Test Center boundary, never in reHEARse
learning attempts, feedback, games or history. No official-score conversion or
placement interpretation is claimed without documented source and scoring
provenance and independent review.

## D033 — Role-specific workspaces and legacy learning routes (LFL-034)

Accepted at the operator's request. The signed-in dashboard must present a

Previously existing reHEARse listening activities, workshop, classroom and

## D034 — Signed-in access and private response caching (LFL-034)

Accepted at the operator's request. Access to learner, teacher and Test Center
resources requires a valid signed-in reHEARse session. This applies to direct
page visits, route handlers, API reads and writes, and media responses; a room
PIN, prior membership cookie, guessed URL or previously opened tab is not a
substitute for an active account session. Role and ownership checks remain
server-authoritative.

Session-bound pages, API responses and app-served media use private no-store
cache policy. Public marketing pages and generic brand assets remain public.
The application must not issue raw public object-storage URLs for authenticated
learning media. This policy governs access through the application; already
published public media URLs must be treated as a separate object-storage
visibility issue and must not be described as revoked by an app deployment.

## D035 — Owner-authorized ETS diagnostic package and immutable retakes (LFL-035)

Accepted at the operator's request. ETS TOEFL ITP Level 1 Volume 3 Practice
Test A is a distinct, assigned ProTEFL Test Center assessment package. The
owner confirmed full rights to digitize and deliver the source to their
students, and explicitly requested that its source PDF, audio, page renders,
answer key, scoring data, and related artifacts be committed in the repository
under `apps/protefl-center/content/`. These assessment records and scores stay
inside the Test Center and never enter reHEARse learning diagnostics/history.

Candidates receive one structured item at a time through authenticated,
assignment-, attempt-, section-, and question-checked private no-store routes.
The complete book, source-page renders, scripts, answer keys, and scoring
tables are not candidate runtime resources. Listening offers a teacher-selected
autoplay or per-question playback mode; autoplay retains the source's roughly
12-second answer windows. Structure is timed at 25 minutes and Reading at 55
minutes. The web-native model preserves explicit Structure Part A omissions,
the exact Part B underlined spans, and Reading source lines/line references.
Learner views render written questions and full choices, not page crops or
page-text dumps.

Invite codes use ten Crockford-style Base32 characters, are stored only as
hashes, remain one-use and expire after seven days. Authenticated claim attempts
are rate-limited per actor. Hiding a resource prevents new starts and retakes
but does not strand an already-started assigned candidate from resuming.

The first completed attempt is the candidate's primary result. Whole-test
retakes append a separate attempt and cannot replace or improve that result.
After full completion, a candidate may also retake Listening, Structure, or
Reading independently. Each focused retake is a child attempt with its own
events, timer, result, and review; it cannot update the parent diagnostic or
participate in the parent's score.
Result details become visible only after completion of all three sections.
The package's exact Practice Test A answer key and score-conversion table are
versioned with source provenance. Deployment and candidate use remain gated on
protected delivery, attempt persistence, timing/audio alignment review, and
end-to-end verification.

## D036 — TOEFL-like Test Center learner and teacher workflow (LFL-038)

Accepted at the operator's request. Learner-facing Test Center branding is
**TOEFL-like Test Center**. Teachers and administrators use a dedicated
teaching workspace with assignment visibility, candidate attempt status,
primary section scores, and child-retake outcomes. Candidate attempt history
and answer keys remain available only to the authenticated assigned learner
after that attempt is complete.

Focused section retries include only incorrect or omitted questions from the
selected completed attempt. A later retry is based on the immediately previous
retry's missed questions, while all retry attempts remain append-only children
of the original full diagnostic. Existing active attempts retain their pinned
settings and answer history. New teacher-issued invites may hide Listening
question text; that setting is pinned into a newly claimed attempt and does not
change active or historical attempts.

Listening playback advances the visible item with the source audio, returns
the view to the active item, and prevents navigation back to passed items.
Structure navigation is separated into Parts A and B with their corresponding
directions; Reading presents the passage before its questions. Student-visible
routes use `/test-center/teaching` for staff controls.

Every attempt pins the package version/content digest plus answer-key, score
table, and timing-map digests. Where the source score table omits Structure raw
counts 39–40, the application leaves the converted result unavailable instead
of extrapolating.

## D037 — Teacher attempt review and reproducible test-package bootstrap (LFL-041)

Accepted at the operator's request. The authenticated teacher/admin workspace
may present the assigned candidate's full-attempt history, section-level
results, section-retake lineage, completion times, and item review showing the
candidate response (or omission) beside the correct choice. This is a staff
capability only; learner answer review remains governed by D035/D036. Attempt
rows and result JSON remain immutable and are never rewritten to build the view.

New full tests are bootstrapped as versioned editable web-native packages with
complete prompts/options, section/part directions, passage structure, keys,
score conversion, audio timing/group maps, provenance, and content hashes. Raw
page screenshots/crops and extracted page-text dumps are private comparison
artifacts only and must never be candidate question content. The repeatable
workflow and publication gates live in
`apps/protefl-center/docs/FULL_TEST_BOOTSTRAP.md` and are required reading for
future package work.

## D038 — Same-account invite claim recovery (LFL-042)

Accepted. A one-use Test Center invite remains bound to the account that first
claimed it. If that same authenticated account re-enters the code while its
assignment is still active and visible, the claim operation is idempotent and
returns the existing assignment without changing invite, assignment, or
attempt records. Re-entry from a different account remains unavailable. This
lets a learner recover after sign-in/session loss without creating a second
assignment or replacing an attempt.

## D039 — Teacher reset as an archived attempt generation (LFL-044)

Accepted. A teacher/admin may reset one assigned candidate for one diagnostic
resource. Reset archives every currently unarchived attempt in that resource
lineage as one audited batch; it never deletes or rewrites answer events,
results, scores, or retake relationships. Candidate current-attempt, history,
media, question, and action queries exclude archived generations, so the next
start begins again at the assigned section's first question. The new root
attempt becomes the current primary while archived primaries remain historical
evidence. Staff history continues to display archived generations and the
reset timestamp; the append-only reset audit records the responsible staff
actor through an opaque ID.

Reset is checked at the teacher/admin server boundary and requires an active
assignment to the named resource/candidate. A confirmation in the teaching UI
warns that an active candidate session will stop immediately. The reset does
not issue a new code, revoke the assignment, or change its pinned scope,
Listening mode, or question-text setting.

## D040 — Private and classroom assignment codes (LFL-046)

Accepted. A teacher/admin chooses an access-code kind when creating an
assignment. A private code preserves the existing single-account claim and
same-account recovery behavior. A classroom code may be claimed by multiple
authenticated learner accounts until its seven-day expiry, revocation, or
resource withdrawal. It is an assignment issuer, not a shared attempt: every
claim creates or finds one learner/resource assignment, and all subsequent
attempts, answers, results, retakes, archives, and history remain isolated by
that learner's opaque actor ID.

Both kinds remain hash-only at rest, rate-limited per authenticated claimant,
same-origin checked, and pinned to the teacher-selected resource version,
delivery scope, Listening mode, and question-text visibility. Existing codes
are migrated as private. Re-entering a classroom code from an account that
already holds the active assignment is idempotent and does not replace its
pinned settings or create another assignment.

## D041 — Focused Listening retakes preserve assigned playback (LFL-049)

Accepted at the operator's request. A focused Listening retake inherits the
autoplay or question-by-question mode pinned to its source assignment instead
of silently forcing manual playback. This applies to newly created retake
attempts; historical and active attempt rows remain immutable.

Autoplay retakes sequence only the selected incorrect or omitted questions.
Each selected item receives the same 12-second answer window as the original
session. For Parts B and C, the first selected item in each conversation or
talk group plays its context before the question; another selected item in the
same group may begin at its own question cue. The candidate may pause and
resume, the view returns to the active item, passed items remain locked, and
the server accepts only the pinned selected sequence before completion.
Question-by-question retakes retain the existing manual playback contract.

## D042 — Assigned-learner password reset with one-time disclosure (LFL-050)

Accepted at the operator's request after backup inspection confirmed that
passwords are stored only as one-way scrypt hashes and therefore cannot be
recovered as plaintext. An authorized teacher may reset only a learner whose
active resource assignment was issued by that teacher. An administrator may
reset any learner with an active assignment to the selected Test Center
resource.

The server generates a high-entropy temporary password, stores only its scrypt
hash, returns the temporary value once in a private no-store response, and
revokes all existing sessions for that learner. The teaching interface keeps
the value only in transient component state and offers copy/dismiss controls;
it is not added to resource DTOs, logs, URLs, analytics, or durable records.

Each successful reset appends an audit row containing the learner, staff actor,
resource, timestamp, and number of revoked sessions. The audit never stores the
temporary password or password hash. Resetting credentials does not change the
learner's assignments, attempts, answers, results, retakes, or archived
generations.

## D043 — Pinned assignment titles and scope-neutral diagnostic restart (LFL-051)

Accepted at the operator's request. Every newly issued private or classroom
code carries a teacher-authored assignment title describing the intended
cohort, learner, or purpose. The title is validated as concise text, stored on
the invite, and copied into each assignment when claimed. It is descriptive
metadata only and never participates in authorization, scoring, resource
visibility, or attempt ownership. Existing invites and assignments remain
valid with a resource-title fallback; the migration must not invent cohort
names or rewrite historical evidence.

The title appears in the one-time issued-code summary, the teaching workspace,
the learner's assigned-resource context, and attempt/history framing where it
helps distinguish multiple deliveries. User-authored title text is rendered as
ordinary escaped text and never as HTML.

Diagnostic restart is defined against a root attempt, not against the literal
`full` scope. The teacher history and archive action must therefore include
root attempts for full diagnostic, Listening-only, Structure-only, and
Reading-only assignments. Archiving a current root also archives its child
section retakes in the same audited batch, preserves every answer and result,
and lets the learner start the same pinned assignment scope again.

This scope-neutral contract is the extension point for later diagnostic
delivery scopes. It does not authorize guessed reset behavior for a different
future resource kind. A resource kind without explicit restart semantics must
return a safe unavailable result until its handler and evidence-preservation
rules are recorded.

## D044 — Teacher-issued full-section restart (LFL-052)

Accepted after operator review showed that assignment-level restart did not
provide the requested per-section control for a learner who had completed a
full diagnostic. A completed full diagnostic exposes separate teacher controls
for Listening, Structure and Reading. Each control appends a new child attempt
covering the entire selected section. It is not a missed-only focused retake
and it does not replace or partially archive the completed full attempt.

When a teacher-issued section reset is completed, the learner's current
diagnostic interpretation is recalculated using the newest completed reset for
that section and the retained results for the other two sections. This current
projection is additive and reproducible from immutable result rows. The
original full-test result remains visible as historical evidence. Learner
missed-only retakes never enter the recalculated score.

The child attempt pins the parent package hashes and assignment settings,
records the authorizing staff actor as an opaque identifier, and remains in the
same immutable section-attempt history. Existing focused retakes and the full
result remain visible. Only an administrator or the teacher who issued the
active assignment may create the restart. The selected parent must be a
completed, unarchived full root for the same assigned learner and diagnostic
resource, and no other unarchived attempt may be in progress for that learner
and resource. Unsupported resources and invalid lineages fail closed.

## D045 — On-demand teacher question reveal and section grouping (LFL-053)

The authenticated teacher/admin attempt review may reveal one missed diagnostic
question at a time when staff selects its row. The reveal endpoint verifies
that the staff actor is an administrator or issued the active assignment, the
attempt belongs to that assigned learner/resource, the attempt has a completed
result, and the requested item is missed in that result. It returns only the
requested item's structured prompt/options and associated Reading passage
when applicable, under private no-store response headers. The teacher view
groups missed items into separate Listening, Structure, and Reading sections;
items in a section are displayed in a single vertical column.

## D046 — Assigned TOEFL vocabulary classification cards (LFL-054)

The reviewed TOEFL frequency list is a versioned learning package, separate
from formal Test Center resources and records. The source has no example
sentences or definitions, and many spellings have multiple part-of-speech
labels. The import therefore merges same-spelling rows into one card, retains
all source labels, and asks which labels the source associates with that form;
it must not imply a context-free word has only one grammatical role or invent
example usage. Source frequency metadata may help a learner select a bounded
study round.

Learner gameplay gives immediate item-level response feedback and supports
returning to a card. Teacher-only assigned-item history may show whether a card
was opened and the learner's item-level response states. It must not calculate
or present an overall score, percent correct, mastery estimate, or aggregate
correctness, and must not enter listening diagnostics or formal Test Center
history. Access codes, learner assignments, attempts and resets use
vocabulary-specific persistence; a private code binds to one learner, while a
classroom code creates isolated learner assignments. Teacher reset archives
the current attempt and preserves its events before a new attempt starts.
